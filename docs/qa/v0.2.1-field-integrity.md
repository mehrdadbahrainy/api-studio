# v0.2.1 persisted-field integrity finding

[Issue #22](https://github.com/mehrdadbahrainy/api-studio/issues/22), QA-021-001,
is a confirmed P1 data-integrity problem in published v0.2.1 (`ee20239`). A
synthetic valid JSON body of 2,000,014 characters is saved with a success
message, but reloading restores only 2,000,000 characters and invalid JSON.
This was executed locally through the Angular browser Save/Reload flow and
the tagged parser. It is not claimed as a native installed-UI reproduction:
the Windows UI helper was unavailable and the personal native workspace was
not modified.

## Unreleased correction

Reject over-limit fields and rows instead of truncating them. Validate before
browser, DPAPI or passphrase-encrypted writes and before accepting native or
Postman imports. Failed request saves retain the unsaved edit and previous
valid saved request. Malformed request lists and duplicate environment IDs
also fail closed.

Persisted-workspace limits, in JavaScript string characters: body 2,000,000;
URL 16,000; Bearer token/Basic password 10,000; Basic username 1,000; request
name 160; Collection/environment/folder names 120; row key 512; row value
100,000; 200 rows per list. These differ from the 5 MiB response limit.

Existing over-limit native vaults remain on disk and may fail validation
instead of opening with silently altered data. Do not delete them. Keep a
private backup and explicitly review oversized values before recovery. This
patch does not repair content that has already been truncated.

## Verification and scope

- Initial field patch: 76 unit and 84 browser E2E cases passed without skips/retries.
  Tagged source passed its original 66 unit/82 browser cases but failed the
  new Save/Reload preservation reproduction.
- Boundary tests cover body/URL/auth/name lengths, row capacities, Postman
  input and encryption; browser tests verify pre-save/pre-restore preservation.
- Genuine installed MSI/DPAPI rejection-and-retry acceptance is added to the
  disposable Windows CI script. Check the fixing PR's actual native CI logs;
  browser/mocked IPC results are not native proof.
- No release version, original tag, installed executable or release assets
  change. A future release requires separate owner approval and passing gates.

Published v0.2.1 cannot receive an unqualified public-introduction GO while
this risk remains in its binary. Passing normal-size soak tests does not
negate the reproducible oversized-data failure.

## Modal keyboard finding

[Issue #24](https://github.com/mehrdadbahrainy/api-studio/issues/24), QA-021-002
(P2), reproduced a real synthetic localhost request after Ctrl+Enter behind
Help. The correction contains and restores dialog focus, supports Escape and
blocks background commands. Browser and installed-MSI regressions cover it.
Unreadable old browser data also blocks ordinary saving until an explicitly
confirmed valid native backup restore; cancelling keeps the original raw data.

The final combined source patch passed 76 unit cases, 87 browser E2E cases,
TypeScript, production build and encoding validation locally. Final native CI
status belongs to the fixing PR checks; it is not inferred from these passes.
